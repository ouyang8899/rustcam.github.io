协议与媒体栈

信令侧通过统一适配器抽象，视频侧对接成熟的媒体服务器。

GB28181

SIP 信令注册、INVITE 呼叫、PS 流解析、平台广播与语音对讲

ONVIF

WS-Discovery 设备发现、ContinuousMove/AbsoluteMove 云台、Backchannel 对讲

RTSP

TCP / UDP 模式接入，支持 RTP over RTSP 直连拉流

WebSocket

事件实时推送与语音对讲双向通道，基于 JWT 鉴权

MAVLink

无人机飞控协议接入（PX4 / ArduPilot），UDP / TCP / 串口连接与指令回执闭环

移动眼 · MOBILE EYE

固定摄像机看住该看的，移动眼盯住会变的。

无人机不是「会飞的摄像头」：它自带飞控，决定去哪看、怎么看、何时回。RustCam 把整套飞行能力接进监控域——Cesium 3D 地球上的实时位置、航线规划、电子围栏与飞行指令，与固定摄像机共用同一套录像、证据链与监控墙。

不新增固定点位

需要时才调度：省掉布线、杆件、点位与后续维护，视觉覆盖按需扩展，而不是提前埋满。

系统架构

清晰的分层，干净的抽象

Axum + Tokio 分层架构：HTTP 处理器 → 应用服务 → 领域模型/端口 → 基础设施实现。协议侧由 SignalAdapter 统一抽象，媒体侧由 MediaServerAdapter 对接媒体服务器。

SignalAdapter 统一协议抽象

GB28181 / ONVIF / RTSP / WebSocket 以同一端口接入，新增协议不改上层业务。

MediaNode 中间件链

承担 G711 ⇄ PCM 转换与重采样，支撑 GB28181 广播与 ONVIF Backchannel 语音对讲。

MediaServerAdapter 媒体适配

同一套媒体服务器接口对接不同媒体服务器，集群化部署无需改业务代码。

快速开始

三步跑起来

克隆仓库、准备依赖、启动服务。

1

克隆仓库

bash
git clone https://gitee.com/ouliuying/rustcam.git
cd rustcam
2

准备数据库与缓存

bash
psql -U postgres -c "CREATE DATABASE rustcam;"
psql -U postgres -d rustcam -f sql/schema.sql
3

构建并启动

bash
cargo build --release
./target/release/rustcam-media

启动 Web 控制台

bash
cd frontend
npm install
npm run dev

桌面客户端使用 CMake 构建 Qt 5/6 工程；完整说明见开发者文档。
