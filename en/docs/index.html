Project layout

crates/rustcam-media/Rust backend library: api / application / auth / domain / infrastructure / protocol / transport / drone_gateway
crates/rustcam-server/Server binary (rustcam-media)
crates/rustcam-drone-service/Mobile Eye control plane: registry, telemetry shadow, leases, commands, geofences, audit
crates/rustcam-drone-adapter/Airborne adapter: MAVLink / PX4 / ArduPilot
crates/rustcam-drone-sim/MAVLink vehicle simulator for tests and demos
frontend/Vue 3 console (Vite + Element Plus + Pinia + Cesium)
testenv/One-command Mobile Eye test environment (start.ps1 / stop.ps1 / screenshots)
clientapp/Qt desktop client (CMake + FFmpeg)
public/Public docs: api.md, architecture.mmd, architecture.png
sql/Database scripts (schema.sql)

Quick start

Initialise the database

bash
psql -U postgres -c "CREATE DATABASE rustcam;"
psql -U postgres -d rustcam -f sql/schema.sql

Start the backend

bash
cargo run
# or a release build
cargo build --release
./target/release/rustcam-media

Start the web console

bash
cd frontend
npm install
npm run dev

One-command Mobile Eye test environment

powershell
pwsh -File testenv\start.ps1
# login: admin / admin123
# built-in MAVLink simulator: PX4 / ArduPilot

Log in and get a token

bash
curl -s -X POST http://127.0.0.1:8081/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'

Configuration file

Edit config.toml at the repository root. Always change the JWT secret and database password in production.

toml
[server]
host = "0.0.0.0"
port = 8081
tls_enabled = false

[database]
url = "postgres://user:pass@localhost:5432/rustcam"
max_connections = 10

[redis]
url = "redis://localhost:6379"
pool_size = 5

[drone]
service_addr = "http://127.0.0.1:50051"

[[media_servers.servers]]
name = "zlmediakit"
url = "http://127.0.0.1:80"
api_key = "your_api_key"
server_type = "zlmediakit"   # zlmediakit / srs / xiu
weight = 100
enabled = true
server_tag = "default"

[jwt]
secret = "change-me-in-production"

API overview

The Axum backend exposes HTTP + WebSocket endpoints under the /api/v1 prefix: 120 protected routes and 15 public routes (19 for the Mobile Eye).

Authentication

Every endpoint except the public ones requires a JWT in the request header: Authorization: Bearer <access_token>

http
Authorization: Bearer <access_token>

FAQ

How are devices onboarded?

Through GB28181 SIP registration, ONVIF WS-Discovery, direct RTSP or WebSocket — all unified into one device and channel model.

What happens when a PTZ device is offline?

GB28181 returns 503 and the adapter automatically re-registers the device.

Is HTTPS supported?

Yes. Set tls_enabled, tls_cert and tls_key in config.toml; HTTPS and WSS are implemented with rustls.

How does two-way talk work?

The MediaNode middleware chain performs G711 ⇄ PCM conversion and resampling, backing GB28181 broadcast and ONVIF Backchannel talk.

Can I try the Mobile Eye without drone hardware?

Yes. The repository ships rustcam-drone-sim, which simulates PX4 / ArduPilot heartbeats, telemetry and command ACKs. Run pwsh -File testenv\start.ps1 to launch the simulator, adapter, control plane, server and web console.

Which flight controllers are supported?

PX4 and ArduPilot over MAVLink, detected automatically from HEARTBEAT.autopilot, with UDP / TCP / serial links.

When will other media servers be available?

The media server adapter is ready; some integrations are still partially implemented — see the module progress table on the features page.
